Should the narrator speak?

Every backend saw the same before/after screenshot pairs and answered the same questions. Labels are known by construction; ambiguous ones are shown but left out of every score.

The gate: announce per backend

Best value per column is highlighted. Brier and ECE: lower is better. Announcements per minute should be close to the labelled rate, not as low as possible.

Calibration

Each dot is a bin of answers: across = the probability the backend gave, up = how often the answer was actually yes. On the dashed diagonal, a backend's 70 % means 70 %. Below it: overconfident. Dot size and the strip underneath show how many answers fell in each bin.

What changed: kind

Rows are the labelled kind, columns what the backend chose; shading is the share of the row. The diagonal is right.

How urgently: urgency

A false interrupt (level 3 for something that is not urgent) talks over the user: the worst mistake a screen reader can make. Rates are out of the pairs that could have had that mistake.

Sensitive content, primary action, fact-checking

Noise: replaying scripted sessions

Each session is consecutive frames of one scripted use of an app, run through the narrator policy with the default thresholds: what a user would actually have heard.

Cost and latency

Latency percentiles skip errored calls. Cached answers replay the latency and price stored with them, so totals are what answering every pair costs, not what this run spent.
